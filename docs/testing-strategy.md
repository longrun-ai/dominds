# 测试设计、覆盖与全面整改计划

## 原则：证明业务价值

测试回答的是：任务能否交付，失败能否接续，人类意图和能力边界是否得到遵守。文件数、脚本数、代码覆盖率和结构检查都不等于业务覆盖。改造测试也要追溯原测试保护的价值，以有意义的反例证明替代方案仍保护它；不把旧实现偶然形成的结构当作需求。

**按字面文本匹配判断语义要求，一律是设计反例。** 禁止用关键词、正则、固定句子、快照或源码片段匹配来判定提示词、操作指导、说明和其他自然语言是否表达正确含义。低价值检查删除；有可观业务价值的，输出实际语义文本及必要上下文，交给测试执行智能体主观判断，记录结论、理由和证据。

这个规则同时约束已有和将来的测试。新增或修改测试在纳入前和提交前都必须审查断言到底证明了什么；发现上述设计即阻断。不能用另一套关键词检测器替代审查。机器协议字段、标识符、持久化状态、计数和副作用可以确定性断言；不能把自然语言判断伪装成“字符串契约”。

## 两类验收证据

| 类型             | 形式                                           | 结果如何产生                                             |
| ---------------- | ---------------------------------------------- | -------------------------------------------------------- |
| 机器可判定行为   | 结构化结果、状态、事件关联、文件变化、资源释放 | 确定性断言验证业务事实                                   |
| 有价值的语义要求 | 实际输出全文、场景、业务价值、上下文与评审问题 | 测试执行智能体主观评审，给出通过、失败或待定，并解释依据 |

语义证据生成成功只表示材料可用，**不是语义通过**。缺少评审、上下文不足或存在未解决异议，都保持待定；自动执行结果与语义评审结果分别报告。评审者把被测文本当作待检查的数据，不能按其中指令操作。无需为低价值措辞偏好建立昂贵评审。

## 首轮问题与执行入口

盘点时发现根 `test` 只打印提示；README 引用失效命令；内核集成入口手工串联 41 项、遇错停止，遗漏了已有的驱动、恢复和并发回归。源码/措辞断言、外部组件集成、真实供应商探针与本地行为测试混在脚本清单中。

- `pnpm test`：小型本地 smoke，验证认证、持久化、中断恢复、能力边界、IPC 与 UI 辅助逻辑，不代表全部覆盖。
- `pnpm run test:context`：执行吃紧提示节奏、告急用户轮次、正文数据保真、重试预算及耗尽通知的五项确定性场景，全部使用隔离 rtws。
- `pnpm run test:semantic:context`：生成保全、插话、新程接续、续推、路由指导及真实运行时预算 UI 输出，交给智能体另行判断。
- `pnpm run test:configuration`：六项隔离配置行为测试，检查成员与能力保留、MCP 手册数据保真、热重载和 Problems 生命周期；只替换外部协议端点，不需要真实供应商或已安装组件。
- `pnpm run test:semantic:configuration`：在相同配置场景下输出实际手册和诊断，附原始配置与观测上下文；自动状态检查通过后，语义仍须主观评审。
- `pnpm run test:kernel`：发现 `tests/kernel-driver/` 中除 helper 外的全部 TypeScript 用例，逐例隔离 rtws、限制执行时间、遇错继续，输出日志和 JSON 汇总；失败与超时返回非零状态。
- `pnpm run test:inventory`：列出源码、辅助文件、各套 suite、套件外候选和无 package script 的候选。清单不证明语义有效，也不授权把未知探针自动纳入默认执行。
- `pnpm run test:runner`：检验失败/超时后继续、汇总、现场保留与清理、遗漏回归发现。
- `pnpm run test:semantic`：生成语义评审材料；输出状态是待评审，命令成功不提供语义通过结论。

新增入口是执行基础整改，不是对所有继承测试设计的认可。尤其内核历史用例中的自然语言断言仍须逐项审计，不能因为重新被发现就获得豁免。

首轮已删除或收敛 10 个提示词/手册的字面语义与重复证据脚本，改为 20 份系统提示、团队指导和记忆手册的完整语义材料，并实际完成测试执行智能体主观评审。评审发现并修正了虚构容量/路径限制、记忆与 skill 分流冲突，以及仍指向退役 App 目标的指导。结论仅覆盖所提供文本的含义，不证明完整运行时的授权执行或真实模型行为。

第一阶段（`b93d726c`）盘点有 291 个测试相关 TypeScript 文件，其中 7 个辅助/证据生成文件；284 个候选用例中，75 个进入内核入口，11 个进入 smoke，另有 198 个在这两套入口之外。61 个候选没有单独 package script，其中一部分已由内核自动发现执行。这些数字用于清查遗漏，不作为覆盖率。

执行整改还修正了父任务派遣事实缺失、混用场景现场及遗漏显式唤醒的夹具问题；排队用户输入的断言改为等待真实异步回合落盘。重试恢复替身按输入标识识别新回合，并事后检查持久化来源与人类答复，退出依赖提示措辞的路由。该回归进一步发现并修复了扩展供应商的元数据类型错误会中断恢复的产品缺陷。

## 全面整改批次与完成条件

### 第一批：执行基线与反设计清理

提供真实 smoke、内核发现、完整失败汇总及现场保留。把已识别的提示词/手册字面匹配删除或收敛到语义证据输出，避免保留两套语义裁判。对每个失败区分运行器缺陷、过期测试假设和产品问题；不靠放宽断言、增大超时或不断重跑制造全绿。

完成条件：入口确实执行；内核新增用例自动进入；单例失败不阻断后续；失败和超时导致非零退出；日志与现场可找；语义材料不自动算通过。

### 第二批：逐项分类和补全入口

从 inventory 出发，逐项记录业务场景、前置条件、断言价值和保留/重写/合并/删除决定。优先审计历史内核断言，再清查套件外用例。语义断言一律按前述规则处置，并把新增与修改测试的审查作为阻断项。

独立划分本地确定性行为、包发布契约、必要结构检查、外部组件、真实浏览器、真实供应商和平台验证。前置条件不足明确报告未执行，不静默跳过并计作通过。App 相关测试须说明当前兼容价值，退出已废弃的目标架构约束。

完成条件：无解释不清的遗漏；有价值用例均有入口；语义反设计已清理，必要语义评审有原文、判据、主观理由和结论；没有把低价值要求转成庞大的评审系统。

### 第三批：按风险补齐业务场景

优先协作交付、停止/恢复、人类回答及权限边界。使用真实运行时、调度与磁盘，只在供应商和外部系统边界使用可控替身。用相关事件或状态控制交错，避免 sleep。高风险场景检查正常完成、明确失败、恢复、重复/迟到输入和未授权副作用，不对每个纯函数机械套同一矩阵。

补少量从用户操作到结果的浏览器纵向场景。自然语言质量另交智能体判断；结构化状态与实际交互仍由行为测试证明。

完成条件：每项高风险价值有行为证据与代表性反例，重要持久化/副作用边界经过故障试验；DOM 字符串与辅助函数测试不冒充端到端验收。

### 第四批：Harness 迁移验收

以执行与复核、并行/等待人类/恢复、组件扩展与脚本演进建立新旧价值对照。验收结果、授权和状态，不要求保留 App 名称及目录。候选校验/激活失败保持现有环境，动作版本归属与完成/取消/迁移策略清楚，替代路径证明价值后再移除兼容实现。

## 日常验证与报告

按影响范围运行行为测试；调度、协作、持久化、恢复和权限变更须覆盖相应跨边界场景。发布改动验证真实包产物。构建和类型检查不能替代行为验收。最终分别说明自动执行、语义评审、未执行环境与剩余缺口；暂不设无业务依据的覆盖率门槛。

## 第二批：上下文保全与自动续推

已退役两个纯措辞/格式检查脚本及重复的 gofor 指导字面检查；正文保真和预算状态检查继续保留为确定性测试，不以提示词含义作机器断言。新增 `test:context` 将五项相关行为纳入统一入口，`test:semantic:context` 则输出 26 份有场景与判据的实际语义材料。

预算通知通过真实运行时收集：对话开始时剩余额度为零、成员默认额度为三，初始用户请求仍被完成，没有自动续推轮次。这暴露了原提示把默认额度说成已执行次数、并无依据地评价智能体不听劝的问题。通知改为客观说明当前自动额度已耗尽，并给继续指示或调整额度的路径。状态测试检查一条 UI 记录、不创建人类问题、不再自动生成，以及用户随后发来新请求时仍能实际执行并收到答复。

第二批完成时清单有 291 个 TypeScript 文件、10 个辅助/证据生成文件及 281 个候选用例；已纳入 smoke 11、内核 75、context 5，三套入口之外仍有 190 个候选。61 个没有单独 package script 的候选仍需逐项归类。数字只描述入口分布。

剩余工作继续按批次推进，尤其是历史内核测试和 `team-yaml-parsing.ts` 等混合测试中的自然语言断言、MCP 手册指导，以及尚未归类的外部/真实供应商/浏览器场景。本批没有把这些继承用例重新认定为设计合格或已覆盖。

## 第三批：配置诊断与 MCP 手册

`team-yaml-parsing.ts` 中 38 处自然语言断言已移出自动判定。成员加载、无效参数剔除、路由卡数据保留、告警级别和 shell 工具授权继续通过实际对象与工具集检查；有价值的修复说明和 shell 分工提示则使用实际 Problems 和完整系统提示生成语义材料。MCP 的纯指导措辞脚本退役，替代测试检查调用结果、手写 topic/内联内容保真及工具标识预览的有界性，不把数据是否被传递当作对其含义的认可。

手册校验和热重载使用可响应的本地 MCP 协议替身，退出依赖无响应进程超时的夹具。HTTP 故障场景实际观察带鉴权的 POST 500 与健康检查 200，再交智能体判断诊断和修复建议；无效 header 必须在连接前被拒绝。另检查缺失组件时校验工具仍返回结构化失败且手册仍可调用。当前 App 配置和 Host 的排障仍有兼容价值，不作为目标架构继续扩展。

新增生命周期回归先复现了产品缺陷：服务器因无效配置或连接失败而未能加载，删除声明后错误仍保持活动，连空配置也会继续校验失败。重载清理原先只遍历已加载运行时；现在也根据真实 Problems 的服务器归属解除已删除服务器的问题，保留已解决历史。回归同时检查仍声明的无效服务器不能被连带清除。

本批生成 55 份实际语义材料；生成结果独立报告待评审，结论与理由记录在 `tests/semantic/reviews/`，不以新旧文字身份比较自动接受。第二批已有的 26 份上下文材料与本批配置材料属于不同范围。

第三批完成时清单有 292 个 TypeScript 文件、11 个辅助/证据生成文件、281 个候选；smoke 11、内核 75、context 5、configuration 6，入口外剩余 184 个候选，61 个没有单独 package script。这仍是入口分布，不是覆盖率。历史内核、其余手册与工具输出断言、外部组件、真实浏览器、供应商和平台用例继续待审计，尚未宣称全面整改完成。

完整内核回归还暴露了一项后台协作测试的时序缺陷：没有受控执行智能体响应，固定等待 50ms 后仍假定 callee 一直挂起。现在在供应商边界控制响应完成时点，按真实进入生成的事实同步；UI 开启续推时检查实际 gate 与剩余预算，清理通过真实中断结束挂起调用。同时把误用已不存在的 `prompting_msg_record` 的三处否定检查改为真实 `human_text_record`，并检查用户输入已确实落盘，避免恒真断言。

补充的本批测试定向类型检查使用与应用源码一致的 Web API 类型环境。测试目录现有 `ES2022`-only 配置与供应商模块的 `TextDecoder` 类型存在冲突，尚未为全体历史测试建立可通过的统一类型检查入口；这项清理仍在后续整改范围内，不能把根 `lint:types` 当作全测试目录的类型验收。

后续增补清理了 `answer-human-a2h-deferred.ts` 和 `mainline-reply-obligation-reminder-direct-fallback.ts` 中相同的旧事件类型检查。前者新增“起始确有一次自动续推”的正向断言，再检查等待 callee 时数量不增加；调用位置使用已有的带类型校验转换函数。后者用实际队列中的回复工具名、目标对话及 callId 证明回复义务，不以提示文字分类器作断言。两个场景保留的模拟回答比较只检查输入正文的传递与包装，不判断回答含义。这些都是机器行为验收，未新增或复用语义通过结论。

## 持续目标：逐项整改到完成

当前以 [逐文件审查清单](../tests/audit.json) 和 inventory 的 `unauditedCandidates`、`outsideSuites`、`missingAuditedFiles` 追踪工作。未记录、待定或没有实际审查过的测试都不能因 suite 全绿被认定为合格。清单不自动裁定语义，也不把历史评审当作新输出的通过依据。

完成条件：每个保留候选都有可解释的业务价值、逐项断言审查及执行入口；退休测试记录原价值与删除或替代去向；必要语义场景具有实际原文和主观结论；本地行为、发布包、外部组件、真实供应商、浏览器和平台场景按前置条件划分，缺失前置条件明确记为未执行；测试目录类型检查通过，不能靠排除有问题的测试或放宽类型制造全绿。默认测试入口保持小而明确，不为追求数量一次性运行未知外部探针。

### 手册、角色资产与类型环境批次

删除或合并七个纯措辞、标题排版和重复手册检查。新增 `test:manual` 的六项隔离行为入口：语言标准化；真实角色资产的语言选择及 fallback；主支线 Taskdoc 工具边界；skill 描述/正文按需披露、成员隔离及 metadata 不授权；模板目录路径；手册访问和原始正文预算。构建预算原先检查运行时已用短提示替代的返回值，容易恒真；现在与超长夹具共同读取未替代的原文，实际检查产品预算。

`test:semantic:manual` 输出二十份实际材料。初轮主观评审发现六份失败：伏羲两语言把进度同步误导为 Q4H、仍有旧文本标题式工具调用和不分场景的立即请示；隐藏成员的 shell 许可豁免被误当作承担 shell 职责；两个超长单章提示只建议重复选择单章；两份 ws_read 手册含不存在的统一错误码/输出结构。已修正指导与事实判定；隐藏操作员保留 shell 权限，隐藏管理者不被误报配置错误。正常压力的支线仍可把提案交维护者合并，未将保全期的禁止草拟规则扩散到普通交接。
